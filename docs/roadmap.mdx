Each item below is a known gap: it is listed on [Limits](/limits) or came out of a hostile review of the project. Status is as of <ZitVersion />. Nothing here is built until it says so, and the order is the current priority, not a schedule.

## Delivered in 0.1.2

Each was on this page or on [Limits](/limits) as a gap.

| Item | What landed | Where |
|---|---|---|
| Batches | `zit accept A B C` and `zit accept --batch`: compose in order, check once, land together; a failing check rejects the batch without bisecting | [CLI](/cli#accepting-several-changes) |
| Parse-check the composed state | merged text with syntax errors neither side had is refused (`[accept] parse_check`) | [zit.toml](/checks#the-parse-check) |
| Renames | a renamed file is compared unit by unit; a pure move writes nothing | [Limits](/limits#semantics) |
| More languages | Java, Ruby, C#; TOML and JSON manifests by top-level key; TypeScript overloads and abstract signatures | [Specification](/spec#3-footprint) |
| Stable-path workspaces | `[workspace] stable_paths` or `zit.stablePaths`: reusable `ws/slot-N` | [zit.toml](/checks#stable-workspace-paths) |
| A port per workspace | `ZIT_PORT`, free at materialisation, not reserved | [Agents](/agents) |
| An agent's output with the change | `zit run --log`, `zit show --log`, `refs/zit/logs/<id>`; the agent's output, not the commands it ran | [Agents](/agents#what-the-agent-printed) |
| `zit doctor` | git, home, copy-on-write, free space, graph, `zit.toml` programs, agents, grammars | [CLI](/cli#the-machine) |
| An integrator for CI | `integrations/github`: a composite action; tested as a script, not yet on Actions | [Working with git](/git#github-actions) |
| Status memo | repeated `zit status` reuses each change's status until current or the evidence changes | [How it works](/science#6-derived-status-no-invalidation-protocol) |
| Usage from Pi | tokens and Pi's price from `pi --mode json` | [Agents](/agents#what-it-cost) |

## Correctness

| Item | Why | Status |
|---|---|---|
| Resolve references by path and import, not only by name | A mention of `Config` depends on every `Config` in the repository ([Limits](/limits#semantics)) | Not started |
| More languages with symbol granularity (C, C++, Kotlin, PHP, Swift, Scala) | Files in those languages are one resource with no inferred reads; Java, Ruby and C# are done | Not started |
| Re-measure false refusals | The 21–23% figure predates the interface-only staleness rule (ADR 16) | Not started |
| Signed evidence | Fetched check results are untrusted by default; trusting them (`zit.trustFetchedEvidence`) trusts whoever can push refs | Not started |
| Run `[[derive]]` and `[prepare]` only from trusted states | A change's own `zit.toml` commands run when you accept or materialise it | Not started |
| Keep agents' branches, tags and stashes out of the real repository | A workspace shares the repository's refs | Not started |
| Stop children of interactive agents | Headless runs stop the agent's process group; interactive runs stop only the agent | Not started |

## From the research

Candidates from [Prior art and objections](/prior-art), each answering a weakness found there. Sizes are estimates.

| Item | Why | Size |
|---|---|---|
| Report false refusals and false accepts against test oracles | Merge-tool evaluations that ignore incorrect clean merges overstate quality (Schesch et al., 2024) | Medium |
| Replay public agent-conflict data: AgenticFlict, CooperBench, STALE | Measured accuracy on other people's data instead of our own runs | Medium |
| A conflict graph from footprints, to pick a batch automatically | Uber's SubmitQueue commits independent changes in parallel; Zit's batch takes the changes you name (or every verified one) and cannot say which member broke a failing check | Large |
| A structure-aware merge for adjacent insertions | Zit's most common remaining rejection; semistructured merge removes it (Apel et al. 2011; Cavalcanti et al. 2017) | Large |
| Compose open workspaces against each other in the background | Crystal's speculative merging warns before anyone records | Medium |
| Measure how much parallelism refused claims give up | Pre-write admission serialised 93.3% of clean cases in Claim Plane (2026) | Small |
| A namespace per workspace | Each workspace has a port (`ZIT_PORT`); other machine-wide state is still shared | Medium |
| A log of the commands an agent ran | `zit run --log` keeps the agent's output; what it ran is still not recorded | Small |
| Select checks from footprints instead of declared `inputs` | Check inputs are trusted, not verified | Medium |
